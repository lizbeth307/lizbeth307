# PCB package: partition, board generator, checks and fab sets

This directory holds the board tool chain of SR-RX-v2.1: the audited partition of the E1–E5 graphs into boards, the area budget, the net classes and DRC rules, the board generator, the independent board check and the fab-set exporter. Everything it produces is a **CI/model result, not a fabrication release**: no board has been made, every fab set says `NOT RELEASED: model/CI only; bench gates OPEN`, and no hardware or bench gate is closed by any tool here. The E1–E5 schematic graphs include whole purchased products, existing board circuitry, cables and physical interfaces as well as custom-board parts; placing all 839 graph references on one PCB would duplicate hardware and invent module pads. The Ukrainian description of the boards, the pipeline and what "DRC 0" proves and does not prove per board is `../build/13-pcb-preparation.md`; the decisions and their reasons are `../build/15-rishennia-komplektu.md` («Плати»).

## Pipeline overview and lineage (wave 2)

Each board `<B>` (PWR_A, PWR_B, RF, CTRL, ENC, HATCH, PACK_FUSE, IMU_CARRIER, T7_INSERT, HDMI_INSERT) runs through the same chain. Steps 1-3 and 5 use the Python standard library only; steps 4 and 6 need `kicad-cli` 10.0.7 and run in `../../.github/workflows/sr-rx-pcb.yml`.

| Step | Tool | Writes | Check | Owner (lineage) |
|---|---|---|---|---|
| 1 Partition and graph audit | `prepare.py` | `generated/*` (below), incl. `generated/b2b-nets.json` (nets between PWR-A and PWR-B) | `python pcb/prepare.py --check` (also in `sr-rx-parts`) | wave 1, then W2 GR-2, GR-3 (domains PWR_BRANCH_SW/USB_POWER_SW, b2b-nets), GR-4 |
| 2 Area budget | `partition_budget.py` reading `partition-spec.json` | `partition-budget.json` (MODEL ESTIMATE) | `--check` (sr-rx-pcb `checks` job) | W2 AREA, then GR-3 |
| 3 Net classes and rules | `stackup.py` | `generated/netclasses.json`, `rules/jlc-4l-1oz.kicad_dru`, `rules/jlc-2l.kicad_dru` | `--check` (`checks` job) | W2 PCB-RULES |
| 4 Board | `board_gen.py` with `boards/<B>.json` | `../build/kicad/boards/<B>/` board, `report.json`, `drc.json`, `connectors.json`, `route-log.json`, SVG | `--check` per board; re-route only with `[pcb-route <B>]` | W2 PCB-PIPE (tool, ENC pilot), then the board packages PCB-PWRA, PCB-PWRB, PCB-RF, PCB-CTRL, PCB-SB1, PCB-SB2 (specs and boards) |
| 5 Independent check | `check_boards.py` | `../build/kicad/boards/<B>/review.json` | `--board <B> --check`, `--all --check` | W2 PCB-RULES |
| 6 Fab set | `fab_export.py` | `../build/kicad/boards/<B>/fab/` (Gerber X2, drill, IPC-D-356, JLC CPL/BOM, fab notes, jobset, manifest; see that directory's `README.md`) | `--board <B> --check` (byte-stable) | W2 PCB-FAB |

A stale board, review or fab set comes back from `sr-rx-pcb` as the artifact `pcb-regenerated-<B>` and is committed as `GENERATED: ...`; none of these outputs is edited by hand. The DC_CORE starter and prototype (`generate_layout.py`, `generate_routed.py`, `../build/kicad/pcb-preparation/`, `../build/kicad/pcb-prototype/`, `../verification/pcb-prototype-review*`) are the historical prototype chain; the wave-2 boards do not use it, and its 71/187/40 contract is unchanged. Order-time checks that CI cannot make (CPL rotation and centroid in the JLC viewer, JLC DFM, LCSC stock on the order date) are build/21 step E1.

## Partition and graph audit (`prepare.py`)

Run from the repository root:

```sh
python pcb/prepare.py
python pcb/prepare.py --check
```

Only Python standard-library modules are used. The script reads E1–E5 and the mount decision of each reference from `design/parts/parts.json` (only the fields listed under `parts_database` in `generated/provenance.json`), verifies actual portable-footprint hashes and pad numbers, and compares every connected graph pin against the real KiCad XML export. `--check` fails for stale generated output, a missing/hash-changed footprint, pin/pad mismatch or graph/XML mismatch.

| Output | Use |
|---|---|
| `generated/partition.json` | Every reference, category, candidate board, unresolved item and constraints |
| `generated/components.csv` | Filterable BOM/placement classification of all 839 references |
| `generated/unresolved.csv` | Missing physical footprint, pin/pad or module/interface/rework blocker records; a connector or feed that is not a board part stays blocking (`interface_mounting_unresolved`) until its parts-database entry fixes both the mating part and the mounting (`interface_resolved`), and a virtual contact whose nets reach no host pin is `host_pads_unconnected` |
| `generated/detector-core-input.json` | Exact 71-part DC core placement input, original pin/net/NC data and eight-net boundary |
| `generated/detector-core-nodes.csv` | All 187 core pin assignments; 180 connected and seven NC |
| `generated/constraints.json` | Current, thermal, RF, DC, grounding and mechanical requirements with sources |
| `generated/provenance.json` | Exact input SHA256s and primary-document URLs |
| `generated/summary.json` | Reproducible counts and audit outcomes |
| `generated/b2b-nets.json` | Nets with pins on both PWR-A and PWR-B, contacts per net and the contact map of the Samtec LSHM-150 pair J208 (PWR-A top) / J209 (PWR-B bottom), which the graph refs carry pin for pin (design input of PCB-PWRA/PCB-PWRB, W2 GR-3, W2 B2B); the map keeps every rail contact between GND contacts (`partition-spec.json` b2b.guard_rule), and `python -I pcb/write_b2b_graph.py` writes it into J208/J209 of `design/E2.json` (`--check` compares) before the refreeze chain |

Existing assemblies are separated from custom-PCB parts. In particular U102/R101/C101/C102 are already on the Adafruit INA228 breakout; U500 represents existing Q6A rail circuitry. R117–R120/C118 are IP2368 module rework, not parts automatically placed on a new motherboard. A407 YAT and A424 TCBT are the opposite exception: these are physical SMT RF parts despite their graph `kind=module`.

The sixteen domains of `prepare.py` are grouped into ten physical boards (`PHYSICAL_BOARD` in `../tools/assembly_data.py`; four main boards PWR-A, PWR-B, RF and CTRL, and six small boards, the encoder board ENC counted once with two instances and a spare). The DC core excludes three first RF tap resistors, their three 100 pF capacitors and twelve hot bleed resistors, keeping these 18 parts at the antenna/RF substrate. Its eight external nets have **no invented connector footprint or pin order**.

All 71 DC core parts now carry graph-assigned portable footprints with MPNs selected in `design/parts/parts.json` (three 0402 series resistors, 29 resistors and 18 capacitors in 0603, 13 SOT-23 and 8 SOT-23-6; exact counts in `generated/summary.json`). A selected MPN is a procurement record, not a qualification: voltage/power/TCR/leakage ratings and land patterns still need review, and the circuit has not passed threshold/RF tests.

The board generator, the checks and the fab sets below are maintained separately from `prepare.py`. See `../build/13-pcb-preparation.md` for boundaries and release gates. No Gerber/drill output is approved by these tools: the fab sets in `../build/kicad/boards/<B>/fab/` are CI/model output, NOT RELEASED.

## Board generator pipeline (`board_gen.py`, wave 2)

`board_gen.py` turns one board spec `boards/<BOARD>.json` into a placed, routed and DRC-checked KiCad board in `../build/kicad/boards/<BOARD>/`. It is a CI/model tool: a passing board is **not a fabrication release**, and no hardware or bench gate is closed by it.

| Mode | Command (from `sat-receiver-audit`) | Needs |
|---|---|---|
| check (default) | `python3 pcb/board_gen.py --board ENC` | KiCad 10.0.7 (`pcbnew` and `kicad-cli`, as in `kicad/kicad:10.0.7`); read-only; fails unless DRC and the audits reproduce the committed `report.json`, `drc.json` and `connectors.json` |
| route | `python3 pcb/board_gen.py --board ENC --route --freerouting DIR` | the same, plus `DIR` filled by `--fetch-freerouting DIR` outside the repository |
| inputs only | `python3 pcb/board_gen.py --board ENC --inputs-only` | standard library: spec, contract and graph projection against the committed report |
| matrix | `python3 pcb/board_gen.py --list-boards` | standard library |

Unit tests use the standard library only: `python3 -m unittest discover -s pcb/tests`.

**Spec.** `boards/<BOARD>.json` (`board_id` = file name) names the contract entry in `../mechanical/generated/contract/boards.json` (outline, holes, hole keepouts, placements), the domains of `generated/partition.json`, the layer plan, the committed project file with the reviewed rule severities, the fab floor (values and source), anchors (fixed refs at fixed coordinates, aligned on the footprint origin, one pad or a pad centroid), placement groups, the pre-route list (scripted locked tracks and zones), post-route pours, height zones and the router limits. Its `instances` block holds one neutral-net template and, per instance, the graph ref and net map and the build quantity (ENC: ENC301 and ENC302 are one design built twice, plus one spare). Footprints, values and pad nets come from `../design/E*.json` and the portable manifest; every instance must give the same neutral pad nets. A `pilot_placeholder` part stands in for a ref that does not exist yet, is named in every report and carries `pending`, the text of its boundary status (ENC J1: `header ref pending GR-3`). `rules_file` must stay `null`: copying a `.kicad_dru` into the board directory and hashing it is not implemented yet, so `board_gen.py` refuses a spec that sets it (PCB-FAB/PCB-SB1 add the copy, the hash and the `--check` comparison).

**Placement groups** (`groups`, each `{id, region: [x0, y0, x1, y1] board mm, side F/B, gap_mm (0.5), decouple_gap_mm (0.25), members: [{ref, rotation, decouple: {ref, pad, max_mm (2.0)}}]}`). A group places template graph parts that have no anchor; placeholders are always anchored. In spec order, the members without `decouple` are shelf-packed into the region by their courtyard boxes after rotation and side (taller first, then by reference; shelves fill left to right from the top of the region). Each member with `decouple` then goes next to that pad of an anchored or already packed part on the same side, nearest free side first, at most `max_mm` from the pin centre to its courtyard box (`place_near`). A placed courtyard box may not overlap another part on the same side or enter a hole keepout, and the region must lie inside the outline; otherwise the spec is refused. The plan is computed with the standard library from the `.kicad_mod` files (SHA256-checked) and placed in KiCad as origin anchors; rotations are multiples of 90°, and side B mirrors x about the footprint position as KiCad's left-right flip does.

**Run.** Board with outline, NPTH holes and copper keepout rule areas (tracks, vias, fills) → footprints placed → scripted copper laid and locked → `pcbnew.ExportSpecctraDSN` → Freerouting → `pcbnew.ImportSpecctraSES` → post-route pours → `kicad-cli pcb drc --format json --severity-all --all-track-errors --refill-zones --save-board` against the committed `<BOARD>.kicad_pro` → audits → `report.json`, `drc.json` (date and path removed, items sorted), `connectors.json` (connector and placeholder pins in board and enclosure coordinates, for the route refresh), `route-log.json`, top and bottom SVG previews. The DSN, the SES and the Freerouting log go to the CI artifact only.

**Audits** (in `report.json`; CI/model results): DRC errors and reviewed warnings counted separately (F14: a warning whose check is not reviewed counts as an error, `ignored_checks` must be empty, unconnected items must be 0); source-pad audit per instance (each graph pin on its pad with the mapped net, no other numbered pad netted, footprint and value as in the graph); boundary audit per instance (each net with graph pins elsewhere ends on a connector pin of the board: `connector`; `provisional` when only a placeholder carries it, and the status names the `pending` text of those placeholders; `dangling` fails); domain coverage; hole keepouts (pads and F.Fab bodies outside; courtyard-box intrusions are reported); THT annular rings against the fab floor; scripted locked copper still present; group placement (each group-placed part at its planned anchor and courtyard box, inside its region, and each decoupling part within `max_mm` of its pin, measured on the saved board).

**Inputs projection (F10).** `report.json` binds the board to hashes of a projection, not of whole files: the spec, the contract fields the board reads (`outline_mm`, `cutouts_mm`, `holes_mm`, `hole_d`, `hole_keepout_d`, `max_component_height`, `edge_zones`, and `origin`, `z_bottom`, `facing` of each placement; `CONTRACT_FIELDS` in `board_gen.py`) with the contract stackup, the project rules, the resolved template (refs, footprints with file SHA256, values, pad nets) and the per-instance graph refs and pins. A change elsewhere in E1-E5, in another contract board or in other fields of this board's contract entry (name, DXF, mount text, area, thermal bonds, later MECH additions such as `height_zones` or `rear_zones`) does not make a board stale; a change of any of these does, and `--check` names the stale part.

**Routing is a frozen output.** `../../.github/workflows/sr-rx-pcb.yml` (push on `wip/**`, `codex/**`, `ccr-*` for the board inputs; one run per ref, `cancel-in-progress: false`) runs the unit tests, then one KiCad job per spec. A board is re-placed and re-routed only when the subject (first line) of the head commit message carries `[pcb-route <BOARD>]` and does not start with `GENERATED:` (fixed regular expression; the message is passed as data and never reaches a shell). The body never counts, so a `GENERATED:` commit may quote the token of its route run and is still only checked. That job also runs `--check` on the new outputs and returns them as the artifact `pcb-regenerated-<BOARD>` (patch plus files), which is committed as `GENERATED: ...`. Without the token the job runs `--inputs-only` and `--check` and fails on any change to the tree.

### ENC pilot (`boards/ENC.json`, `../build/kicad/boards/ENC/`)

First routed in run 42389609473; the committed board comes from route run 42394570471 (KiCad 10.0.7, Freerouting 2.5.0 JAR), re-routed because the review fixes changed the `contract` projection and the spec (same 8 segments, 0 vias and placements): DRC errors 0, unconnected 0, `ignored_checks` [], 7 reviewed `silk_over_copper` warnings (the legend rectangle of the vendored PEC11R footprint crosses its own pads; the fab clips legend over copper); source-pad audit 0 errors for ENCM (ENC301) and ENCV (ENC302); boundary audit `provisional: header ref pending GR-3`. The board is 2-layer, 24 x 24, with two NPTH 2.7 mm holes and 6.0 mm copper keepouts; the PEC11R sits at the contract `encoder_at` (12, 12), rotation 90; a scripted locked GND link J1.1 → ENC.C runs on B.Cu (0.5 mm); Freerouting routes A and B on F.Cu (0.25 mm, no vias); GND pours on both layers. All 67 KiCad 10.0.7 DRC checks are `error` in `ENC.kicad_pro` except the 12 listed with reasons in `drc_policy` of `boards/ENC.json`; the rules sit above the JLC 1-2 layer floor read on 2026-11-07 (`fab_floor`).

Pilot limits, kept OPEN for the packages named:

- **J1 is a `pilot_placeholder`**: the 2.0 mm 4-pad land `PinHeader_1x04_P2.00mm_Vertical` of the KiCad 10.0.7 library, pins GND, A, B, PRESS as in `build/16-dzhgut-rozyemy.csv:48` and `:49` (X37S0-ENCM / X38S0-ENCV).
