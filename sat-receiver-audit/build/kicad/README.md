# KiCad SR-RX-v2.1 — відтворення схем і перевірок

> **Стан 20.10.2026:** ПЗ керування Pico/IMU та labd/labctl реалізоване й пройшло хостові тести; див. [актуальний запуск](../../software/README.md). Фізичне встановлення/приймання не виконано. Старі фрази про відсутню прошивку нижче описують етап 19.10.

Поточна редакція від 19.10.2026 генерується локальними Python-інструментами з `design/E1.json`–`E5.json`. У вихідному коміті Claude `4653188` усі п'ять електричних E1–E5 були порожніми; тому історичний опис «побудовано через KiCad MCP» нижче не підтверджує походження поточних схем.

## Склад актуального комплекту

- `sr-rx-v2.kicad_pro` / `sr-rx-v2.kicad_sch` — проєкт і кореневий зміст. E1–E5 поділяються генератором на додаткові електричні сторінки; їхній точний перелік — `generation-manifest.json`.

Креслення (з 23.10.2026). Кожна функціональна група — окремий блок на одній сторінці: заголовок один раз, примітки OPEN/TBD поруч із її частинами. У рядку сигнал іде зліва направо: мікросхеми, модулі, транзистори й послідовні елементи стоять на сигнальній лінії, підтягувальні резистори й контрольні точки — над нею, шунтові елементи (розв'язувальні конденсатори, дільники, TVS, демпфери) — під нею, земля — символ GND унизу. Контакти однієї мережі в рядку з'єднано ортогональними дротами з точками на T-з'єднаннях; контакт, до якого дріт довелося б вести довгим обхідним шляхом, отримує мітку. Кожне дерево дротів має рівно одну глобальну мітку з канонічною назвою мережі (рамка-стрілка — мережа виходить за межі групи, пряма рамка — мережа лише цієї групи), бо локальну мітку KiCad перейменував би на «/<аркуш>/<назва>» і змінив би netlist. Транзистори й діоди мають стандартні графічні символи KiCad (Device: Q_NMOS/Q_PMOS, D, D_Zener, D_Schottky, LED) з незмінною нумерацією контактів. Генератор сам відновлює зв'язність кожної сторінки з геометрії (кінці дротів, контакти, мітки, GND) і не записує сторінку, де вона розходиться з графом.
- `sr_rx_v2_completed.kicad_sym` — бібліотека з поточних графів; початкові `sr_rx_v2_pwr.kicad_sym` / `sr_rx_v2_sig.kicad_sym` збережені. Бібліотечні шляхи відносні.
- `sr-rx-v2.pdf` та `svg/` — результати CLI-експорту після успішних перевірок; не результат вимірювання заліза.
- `../../verification/erc.json` — повний сирий ERC; `validation.json` — незалежне зіставлення netlist із графами; інваріанти й розрахунок DC-detector — окремі відтворювані перевірки.

Розширені позначення нових детекторів E4 використовують R/C4400–4499; старі діапазони 100–599 збережені для початкових вузлів. Бібліотека відображає фізичні контакти IC і явно названі функціональні інтерфейси готових модулів; останні не є вигаданою нумерацією pad невідомої плати.

## Команди

З каталогу `sat-receiver-audit`, у Python 3 з установленим KiCad 10 CLI. Для офлайн-HTML додатково потрібні Pandoc і Python-залежності з `tools/requirements.txt` (`python3 -m pip install -r tools/requirements.txt`):

```bash
python3 tools/run_checks.py --export
python3 tools/build_bundle.py
```

Другу команду виконувати після успішного завершення першої. Якщо CLI не в PATH:

```bash
python3 tools/run_checks.py --kicad-cli /повний/шлях/до/kicad-cli --export
```

`run_checks.py` послідовно генерує схеми, експортує XML netlist, записує ERC, порівнює мережі, перевіряє незалежні електричні інваріанти та DC-detector, формує документи й за `--export` PDF/SVG. `build_bundle.py` пакує офлайн-HTML із вихідним архівом. Пакування не замінює перевірки. Запуск 23.10.2026 завершено: 750 елементів, 2181 контакт, 466 мереж, 14 сторінок разом зі змістом (13 електричних); ERC 0 помилок і 0 попереджень, netlist PASS; повторний запуск дає байт-у-байт ті самі файли. Після будь-якої зміни графів ці результати потрібно отримати повторно.

PDF експортується без property popups та hierarchical links: у використаному KiCad 10.0.7 початковий експорт з анотаціями повертав exit 0, але неповний PDF. Генератор додатково перевіряє завершення `%%EOF`; 14-сторінковий PDF від 23.10.2026 перевірено окремим PDF-парсером і візуально ([звіт](../../verification/pdf-visual-review.md)).

## Межа готовності

**Апаратний випуск BLOCKED.** ERC та збіг netlist не перевіряють фізичну ревізію модулів, нагрівання, струм запуску, USB/PCIe SI, RF, калібровку батарейного ADC або механіку. [OPEN_ITEMS](../../OPEN_ITEMS.md) і [v2.1](../12-revision-v2.1.md) мають бути прочитані до монтажу. ISDT/raw-balance та щомісячне балансування заблоковані до E1-02; J102 DNP/service-only.

`sr-rx-v2.kicad_pcb` — порожній шаблон, не розведена плата. Footprint у символі не є доказом готовності PCB. Власна прошивка/сервіси не реалізовані; `readiness-contract.json` не керує GPIO. Монтаж USB/роз'ємів — тільки за [E5 connection guide](../../design/E5-connection-guide.md), компоненти й зовнішній S-band вузол — за [12-revision-v2.1](../12-revision-v2.1.md). Старі габарити й кошторис v2 не є підтвердженим кошиком нової редакції.

## Як підключити той самий MCP сервер у себе
Сервер: [mixelpixx/KiCAD-MCP-Server](https://github.com/mixelpixx/KiCAD-MCP-Server) v2.8.2 (MIT). Він працює через stdio JSON-RPC, а для живої роботи з відкритим KiCad є експериментальний режим через IPC API.

Потрібно:
- KiCad 10 (на Ubuntu — PPA `kicad/kicad-10.0-releases`);
- Node.js 20+;
- Python з модулем `pcbnew`.

Встановлення:

```bash
git clone https://github.com/mixelpixx/KiCAD-MCP-Server.git && cd KiCAD-MCP-Server
python3 -m venv --system-site-packages venv && ./venv/bin/pip install -r python/requirements.txt
npm install && npm run build
claude mcp add kicad -- node "$PWD/dist/index.js"
```

Конфігурація для інших клієнтів:

```json
{ "mcpServers": { "kicad": { "command": "node", "args": ["/шлях/KiCAD-MCP-Server/dist/index.js"],
  "env": { "PYTHONPATH": "/usr/share/kicad/scripting/plugins", "KICAD_AUTO_LAUNCH": "false" } } } }
```

На що зважати:
- **Бібліотеки символів.** Якщо KiCad ще жодного разу не запускали, скопіюйте `/usr/share/kicad/template/sym-lib-table` у `~/.config/kicad/10.0/`, інакше сервер не бачить стандартних бібліотек.
- **Тайм-аут пошуку.** Перший `search_symbols` індексує всі бібліотеки, і це може тривати понад 30 с. Такий запит обривається вбудованим тайм-аутом сервера, тому збільште його.
- **Конфлікт Python.** Не додавайте `/usr/lib/python3/dist-packages` у `PYTHONPATH`, якщо версія Python у venv інша, ніж у системі: тоді не завантажується Pillow.
