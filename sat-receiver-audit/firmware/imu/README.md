# Зовнішній IMU pack: RP2040-Zero + Adafruit BNO085 №4754

Реалізовано переносний парсер SHTP/SH-2, стан конфігурації BNO085 і MicroPython
адаптер SPI0 → UART0. Модульні тести перевіряють байтові формати, помилки, вік
даних, черги та поведінку підставлених SPI/UART. На реальній платі цю прошивку
ще не запускали. Допуск до роботи з обладнанням залишається заблокованим до
виконання перевірок нижче та загальних hardware gates проєкту.

## Підключення за E3/E5

Це призначення проводів **цього проєкту**. Числа GP — номери GPIO RP2040;
позначення BNO — написи на платі Adafruit №4754. Невідомий сторонній модуль
із написом «BNO085» потребує окремої перевірки схеми й розпіновки.

| RP2040-Zero | Adafruit BNO085 / інше з'єднання | Призначення |
|---|---|---|
| GP0 / UART0 TX | `IMU_TX` → головний Pico GP9 / UART1 RX | Телеметрія 115200, 8N1, логіка 3,3 В |
| GP1 / UART0 RX | `IMU_RX` ← головний Pico GP8 | Зарезервовано; Pico тримає GP8 високоімпедансним входом (канал лише на прийом), вхідні байти відкидаються |
| GP2 / SPI0 SCK | `SCL` | Такт SPI |
| GP3 / SPI0 MOSI | `DI` | Дані до сенсора |
| GP4 / SPI0 MISO | `SDA` | Дані від сенсора |
| GP5 | `CS` | Вибір SPI, активний низький |
| GP6 | `INT` | H_INTN, активний низький; фіксується час спаду |
| GP7 | `RST` | Reset сенсора, активний низький |
| GP8 | `P0` / PS0 / WAKE | Спочатку високий; після першого INT дозволено WAKE=0 |
| 3V3 | `P1` / PS1 | Постійний високий для SPI |
| 3V3 | `P0` через зовнішній резистор **1 кОм** | Перекриває штатний pulldown 10 кОм Adafruit |
| 3V3 | `VIN` | Живлення BNO-плати на рівні логіки RP2040 |
| GND | `GND` і земля UART-джгута | Спільна земля |
| `5V` / вхід живлення Zero | `E5_IMU_VIN` після діода D502 | Захищені 5 В від корпусного роз'єму E5 |

Нумерація GX16-4 та захист джгута визначені в
[E5 connection guide](../../design/E5-connection-guide.md). Розводку потрібно
звірити з [E3.json](../../design/E3.json) та реальною ревізією Zero/Adafruit.
Не ставити 10 кОм замість зовнішнього 1 кОм PS0: дільник з двох 10 кОм
створить невизначений рівень вибору режиму. BOOTN/BT має залишатися у
штатному режимі запуску сенсора, а P1 — високим до зняття RST. SPI/strap
проводка повинна пройти перевірку до подачі живлення на pack.

## Файли та встановлення

Цільовий API — MicroPython **v1.26.0, порт RP2**. Конкретний UF2 для
RP2040-Zero, його контрольна сума, обсяг flash і версія порту ще потребують
перевірки на платі. CPython використовується для тестів переносних модулів.

1. Зняти живлення джгута. Під'єднати pack до USB для прошивання й перевірки;
   можливість одночасного живлення USB/джгутом спочатку перевірити за E5.
2. Встановити перевірений RP2 MicroPython UF2. Залишити REPL на USB.
3. Скопіювати в корінь файлової системи Zero п'ять файлів:
   `main.py`, `shtp.py`, `session.py`, `device.py` з цієї папки та
   `wire.py` з [software/srrx/wire.py](../../software/srrx/wire.py).
   `__init__.py` потрібний лише для імпорту пакета в тестах CPython.
4. Перевірити імена й контрольні суми копій, від'єднати USB, виконати холодний
   запуск із захищеного входу E5 та записати UART-трасу й сигнали логічного
   аналізатора. Команди встановлення на віддалений пристрій у цьому репозиторії
   автоматично не виконуються.

`main.py` задає частоту CPU 125 МГц; SPI0 1 МГц, mode 3 (CPOL=1, CPHA=1),
MSB first; UART0 115200 8N1, RX buffer 128, TX buffer 512. Рівень PS0
встановлюється до імпорту переносних модулів. Reset утримується низьким
10 мс, після зняття очікується перший INT не довше 1 с. PS0 залишається
високим до першого INT; тільки потім він використовується як WAKE.

Час спаду INT фіксує короткий hard IRQ. Обробка SHTP, JSON і UART відбувається
в основному циклі. Кожне звернення SPI має одну пару CS=0/CS=1; довжина
прийнятого пакета визначає число тактів. Під час запису команди одночасний
вхідний пакет також обробляється. Перед кожною порцією UART цикл обслуговує
SPI. Відсутній INT, помилка SPI або невідповідний пакет запускають health
EVENT та обмежений повтор reset/configure через 1 с.

## Дані й обмеження протоколу

Після Product ID (`F9`/`F8`) прошивка вмикає Rotation Vector **0x05 з періодом
200000 мкс (5 Гц)**, надсилає Get Feature і перевіряє точну відповідь `FC`.
Ранні звіти між Set Feature й підтвердженням перевіряються та відкидаються.
Продукт/версія з відповіді входять у HELLO. Код перевіряє форму Product ID,
але перелік схвалених версій BNO085 ще треба сформувати з реального модуля.
Як у CEVA `sh2.c`, один cargo може містити кілька 16-байтних записів `F8`:
кожен перевіряється, у HELLO іде перший; неповний чи змішаний cargo дає помилку.
Стартовий звіт Initialize (`F1`, команда `0x84` = INITIALIZE|UNSOLICITED, або
`0x04`) приймається лише до Product ID; пізніше він означає reset сенсора.
Під час стартового дренажу UART-черга обслуговується, тож health EVENT не
перевищує свого 100 мс терміну.

Парсер підтримує формат Game Rotation Vector 0x08 для тестів і майбутньої
конфігурації. Робочий сеанс вмикає лише 0x05; вхід 0x08 у ньому є помилкою.
Це виключає змішування двох систем відліку та неперевірене зростання потоку.

| Поле `EVENT.p.imu` | Значення |
|---|---|
| `ok`, `fresh` | `true` лише для нового перевіреного звіту зі статусом 1–3 |
| `quaternion` | `[x,y,z,w]` = `[i,j,k,real]`, signed Q14 / 16384 |
| `report_id` | 5 |
| `status` | SH-2: 0 unreliable, 1 low, 2 medium, 3 high |
| `heading_accuracy_rad` | Штатна оцінка точності звіту 0x05, signed Q12 / 4096 радіан |
| `sample_seq` | 8-бітний номер звіту сенсора; перевіряється послідовність |
| `age_ms` | Вік від sensor timebase/INT + обробка SPI + консервативні 150 мс для UART |
| `at_ms` | Локальний час обробки Zero modulo 2³²; між платами не синхронізований |

Перевіряється квадрат норми кватерніона 0,90…1,10; значення автоматично не
нормалізуються. Нульовий/некоректний кватерніон, від'ємна точність, вік
≥500 мс, майбутня мітка часу, пропуск/повтор звіту або невідомий report
дають `ok:false, fresh:false, quaternion:null, error:...`. Статус 0 також
відкриває лише health EVENT. Відновлення після нього потребує нового доброго
звіту; попередня орієнтація не повторюється. Після інших помилок потрібний
reset/configure. Тиша 500 мс позбавляє сеанс чинності.

SHTP має ліміт 512 байт включно з 4-байтним заголовком і окремі лічильники
для кожного каналу/напрямку modulo 256. Заголовки continuation у цій реалізації
відхиляються з reset; фрагментовані SHTP cargo не збираються. Звичайне
розбиття байтів одного пакета між викликами парсера підтримується. SHTP/SPI
не додає CRC, тому перевірки форми й норми не доводять відсутність усіх
можливих пошкоджень SPI.

UART використовує [спільний протокол](../../software/PROTOCOL.md):
`@<JSON>|<CRC16-CCITT-FALSE>\n`, не більше 512 байт. HELLO має `role:"imu"`,
`protocol:1`; він іде першим, повторюється щосекунди й перед добрим EVENT
після health-помилки. `s` — випадковий ненульовий nonce цього pack,
`q` строго зростає; до переповнення MCU перезапускається watchdog і видає
новий nonce. Це окремий телеметричний сеанс, не засіб автентифікації.
Головний Pico перевіряє nonce/послідовність, додає власний час приймання та
передавання і передає `p.imu` далі. Команд калібрування, tare або запису DCD
через UART ця прошивка не виконує.

Черга містить щонайбільше два закодовані кадри (1024 байти); кожен повністю
передається в UART не пізніше ніж за 100 мс після створення. Запис має порції
до 32 байт і починається лише після `UART.txdone()`, щоб не чекати звільнення
переповненого TX buffer. Залишок короткого запису зберігається. Помилка чи
тайм-аут UART припиняє видачу даних; WDT 2 с перезапускає Zero. Частково
початий рядок не обрізається під час звичайного відкидання черги.

Штатна оцінка точності не встановлює факт завершеної калібровки, якість
магнітного монтажу або напрямок на географічну північ. Прошивка не обчислює
heading, declination, координати GNSS чи результат апаратного PASS.

## Перевірки перед апаратним допуском

Модульні тести з кореня репозиторію:

```sh
PYTHONPATH=software:. python3 -m unittest discover -s software/tests -p test_imu.py -v
```

Апаратні результати потрібно записати окремо; наведені нижче пункти залишаються
**OPEN** до вимірювання.

| Gate | Що потрібно довести на реальному pack |
|---|---|
| Плата й живлення | Ревізії Zero/Adafruit, відповідність E3/E5, правильні 3,3 В на BNO VIN/логіці, захист і відсутність backfeed |
| Режим запуску | PS1/PS0 високі перед RST і до першого INT за холодного старту, reset MCU, brownout; 1 кОм долає штатний pulldown |
| SPI | CPOL/CPHA, CS/WAKE, цілий пакет в одній транзакції, обробка одночасного MISO під час запису, реальні startup advertisements ≤512 байт без continuation |
| IRQ й час | IRQ позначає саме спад INT; обслуговування типово ≤10 мс за CEVA; відсутня втрата IRQ під GC, UART, reset і навантаженням |
| SH-2 | Реальні Product ID/firmware і число записів `F8` у cargo, стартовий Initialize `0x84`, період 200000 мкс у FC, документовані Q14/Q12 підтверджені metadata/контрольними орієнтаціями |
| UART й вік | На обраному RP2 UF2 `txdone` охоплює весь TX; 32-байтні write не блокують SPI; черга вкладається у 100 мс, бюджет 150 мс консервативний |
| Відмови | Від'єднання BNO/UART, обрив INT/MISO, затримка ≥500 мс, reset, bad length/sequence/continuation → жодної чинної старої орієнтації |
| Геометрія й середовище | Знаки/порядок осей, орієнтація корпусу, магнітні завади від живлення/кріплень та поведінка status0…3 перевірені стендом |
| Наскрізний тракт | Pico/Q6A додають реальні затримки; новий nonce/replay/gap і втрата HELLO не дозволяють прийняти старий кадр |

## Первинні джерела

- [CEVA BNO080/085/086 datasheet, 1000-3927 v1.17](https://www.ceva-ip.com/wp-content/uploads/BNO080_085-Datasheet.pdf): SPI, PS0/WAKE, reset/INT, SHTP, часові вимоги.
- [CEVA SH-2 Reference Manual, 1000-3625 v1.9](https://www.ceva-ip.com/wp-content/uploads/SH-2-Reference-Manual.pdf): Product ID, Set/Get Feature, reports 0x05/0x08, статус і Q-формати.
- [CEVA SH-2 reference implementation](https://github.com/ceva-dsp/sh2): `sh2.c` (base/rebase/delay), `sh2_SensorValue.c` (декодування), `shtp.c` (канали/послідовності).
- [Adafruit BNO085 pinouts](https://learn.adafruit.com/adafruit-9-dof-orientation-imu-fusion-breakout-bno085/pinouts) і [офіційна бібліотека](https://github.com/adafruit/Adafruit_BNO08x): позначення виводів і вимоги SPI.
- [MicroPython v1.26.0 RP2](https://docs.micropython.org/en/v1.26.0/rp2/quickref.html), [Pin](https://docs.micropython.org/en/v1.26.0/library/machine.Pin.html), [UART](https://docs.micropython.org/en/v1.26.0/library/machine.UART.html), [RP2 UART source](https://github.com/micropython/micropython/blob/v1.26.0/ports/rp2/machine_uart.c): API, IRQ, UART buffers/timeout/txdone.
