# База деталей SR-RX-v2.1

Джерело правди для посадкових місць, MPN, виробників, SKU дистриб'юторів і альтернатив усіх 777 позначень схеми (графи [E1](../E1.json)–[E5](../E5.json)). Рішення, на яких вона стоїть, — у [build/15-rishennia-komplektu.md](../../build/15-rishennia-komplektu.md). Наявність MPN — факт закупівлі, а не кваліфікація деталі: апаратні ворота лишаються OPEN.

## Файли

| файл | що містить |
|---|---|
| `parts.json` | записи деталей (схема нижче); кожне позначення схеми входить рівно в один запис |
| `snapshots/<дата>-lcsc.json` | знімок LCSC: виробник, MPN, корпус, атрибути, склад, ціни, клас бібліотеки JLC; пише `tools/check_parts_availability.py` |
| `snapshots/<дата>-manual.json` | прочитані вручну сторінки DigiKey DE та інших продавців: URL, дата, метод, MPN, склад (або «не показано»), ціна |

## Генератор і перевірка

- `python tools/build_parts.py` записує в `design/E*.json` поля `footprint`, `mpn`, `manufacturer`, `lcsc`, `alt_mpn`; маніфест, README і `fp-lib-table` бібліотеки футпринтів; [10-zakupivlia.md](../../build/10-zakupivlia.md) / `.csv`, `10-jlc-bom.csv` і `10-parts-coverage.json`.
- `python tools/build_parts.py --check` нічого не пише і падає, якщо база неузгоджена або будь-який вихідний файл застарів. Працює офлайн, лише stdlib.
- `python tools/make_footprints.py [--check]` пише (перевіряє) власні футпринти `SR_RX_Custom.pretty` з розмірів креслень виробника; `--fetch` докачує офіційні футпринти KiCad 10.0.7.
- `python tools/check_parts_availability.py --date РРРР-ММ-ДД` — лише з мережею: перечитує всі коди LCSC через публічний пошук JLCPCB (без ключа API) і пише новий знімок. В офлайн-регресії не запускається; `--check` лише попереджає, коли найновіший знімок старший за `policy.snapshot_max_age_days`.
- Робочий процес `.github/workflows/sr-rx-parts.yml` запускає обидві перевірки, звіряє кожен офіційний футпринт байт у байт із бібліотекою образу kicad/kicad:10.0.7 і розбирає всі футпринти через `kicad-cli`; знімок наявності — лише за ручним запуском, як артефакт (у Git нічого не комітить).

## Що перевіряє `--check`

1. Кожне позначення графів — рівно в одному записі; невідомих позначень і невідомих ключів немає.
2. Для монтажу на плату (`pcb_*`) є футпринт із бібліотеки проєкту; кожен вивід графа має площадку, а кожна площадка — це вивід графа або пояснена в `unused_pads` (PIN-01); полярна деталь не має виводу 1/+ на GND.
3. Кожна куплена деталь (не DNP) має MPN і виробника, SKU зі знімка (MPN у знімку збігається) або `source`, а також альтернативу або причину `single_source`; інакше — `tbd` з причиною.
4. Для пасивних номінал, допуск, потужність, TCR, напруга й діелектрик з рядка графа порівнюються з атрибутами LCSC основної деталі та кожної альтернативи; дозволене відхилення — лише записане в `deviation` з посиланням на рішення.
5. Для інших деталей `match` має входити в рядок номіналу графа, тож граф і база не розходяться мовчки.
6. `virtual` має `host`: деталь-господар на платі з футпринтом.

## Запис `parts[]`

| ключ | значення |
|---|---|
| `id` | стабільний ідентифікатор запису |
| `mount` | `pcb_smt`, `pcb_tht` — деталь на платі; `pcb_pad` — площадка без покупки (TP, net tie); `pcb_module` — модуль, що паяється на плату; `module` — готовий модуль; `panel`; `harness` — кабель або джгут; `remote` — виносна деталь на дротах; `rework` — переробка готової плати; `on_module` — деталь усередині купленого модуля (не купується); `existing` — порт наявної плати Q6A; `assembly` — інтерфейс зібраного вузла; `virtual` — частина іншої деталі |
| `refs` | позначення схеми |
| `kind`, `package` | тип і корпус (для пасивних — розмір 0402…2512) |
| `footprint` | `Бібліотека:Назва` з `build/kicad/footprints` |
| `manufacturer`, `mpn` | основна деталь для замовлення |
| `sku` | `lcsc`, `digikey`, `mouser`, `tme`, `web` — ключі записів у знімках |
| `alternates[]` | `manufacturer`, `mpn`, `sku`, `note` — допустимі заміни |
| `extras[]` | супутні деталі (`item`, `manufacturer`, `mpn`, `sku`, `qty_per_ref`): тримачі запобіжників, корпуси й контакти роз'ємів, ферити |
| `match` | частина рядка номіналу графа, яку має містити кожне позначення |
| `single_source` | чому немає альтернативи |
| `tbd` | чому MPN або SKU не підтверджено (запис лишається в BOM як відкрита позиція) |
| `source` | продавець з оцінки v2 (`build/10-bom.csv`), сторінку якого 24.10.2026 не перечитано |
| `deviation` | `tolerance_pct`, `reason`, `decision` — свідоме відхилення від номіналу графа |
| `unused_pads` | площадка → причина, чому вона без кола |
| `host` | для `virtual`: позначення → позначення деталі-господаря |
| `polarized`, `note` | полярність для перевірки; примітка |

## Правила вибору

- MPN, названий власником аркуша в графі (у номіналі або полі `mpn`), лишається основним, якщо його можна замовити; деталь з наявністю LCSC з тими самими атрибутами стає альтернативою. Для MLCC з вимогою E2 щодо DC bias заміна допустима лише після перевірки ефективної ємності.
- Для решти пасивних — деталь LCSC з перевіреними атрибутами, з перевагою базовій бібліотеці JLC, і альтернатива іншого виробника.
- Запас пасивних на платах: +10 %, щонайменше 5 шт. (`policy.spares`).
- Склад і ціна — показання на дату знімка, не резерв. Ціни в BOM не замінюють перевірки кошика перед замовленням.
