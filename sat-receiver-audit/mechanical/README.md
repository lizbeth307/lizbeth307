# Механічна модель SR-RX-v2.1

Параметрична модель корпусу, середньої пластини, плат, РЧ-відсіку й антенних деталей (build123d). З одного набору параметрів генеруються STEP/STL, креслення SVG/DXF/PDF з розмірами, контур плат для KiCad і звіт посадки.

> **MODEL FIT ONLY.** Модель перевіряє конверти деталей, дані з даташитів і геометрію корпусу між собою. Вона не замінює примірку: ворота посадки, ущільнення (T-07), тепла (T-02, T-03), падіння й решта апаратних воріт лишаються **OPEN**. Жоден результат цієї теки не є апаратним PASS.

## Що де

| шлях | зміст |
|---|---|

| `params/parts.json` | конверти й дані деталей; у кожної — `status` (datasheet / repo / listing / assumption) і `src` з URL і датою прочитання |

| `params/antennas.json`, `params/imu_pack.json` | розгортки антен, оправки, затискачі Yagi, вузол S-band, пак IMU та його осі |
| `params/vendor-models.json` | STEP постачальників, які CI завантажує із зафіксованим SHA-256 (у Git не комітяться) |
| `srrx_mech/` | генератор: `cad.py` (3D), `cad_fixtures.py` (антенні й IMU деталі), `drawings_*.py`, `boards.py`, `antennas.py` (креслення), `layout.py`, `rules.py`, `interference.py`, `thermal.py` (перевірки), `writers.py`, `export3d.py` (SVG/DXF/PDF, STEP/STL) |

## Результати (`generated/`)

|---|---|
| `step/*.step` | кожна деталь окремо та `assembly.step` (деталі + конверти-резерви з назвами `envelope:*`; це не геометрія постачальників) |

| `drawings/M-*.svg/.dxf` | корпус: лице (M-01), верх і низ (M-02), бокові стінки (M-03), задня стінка (M-06), пластина 1:1 з таблицею отворів (M-07), кутники (M-08), РЧ-відсік FR4 (M-09), п'єдестал Lime, бобишка UFS, мідний блок (M-10), екран HF+ (M-11), безель (M-12), шов і лючок (M-13) |
| `drawings/B-*.svg/.dxf`, `boards/*-edge-cuts.dxf` | контури плат з отворами; `*-edge-cuts.dxf` містить лише CUT і HOLE для шару Edge.Cuts KiCad (1 одиниця = 1 мм) |
| `drawings/A-*.svg/.dxf` | антени 1:1: пелюстки гелікона (A-01, A-02), диск (A-03), сегменти рупора QO-100 (A-04, A-05), конус LNB (A-06), штанга Yagi (A-07) |
| `drawings/P-01, P-02, I-01` | зовнішній S-band вузол (Hammond 1554U2GY) і пак IMU (Hammond 1550Z101) |
| `drawings/*.pdf` | ті самі аркуші, по одному PDF на групу; друкувати 100 % (на кожному аркуші — контрольна лінійка 100 мм) |

| `fit-report.json`, `fit-report.md` | звіт посадки (усе — модель) |
| `vendor-fit.json` | звірка параметрів Q6A зі STEP Radxa V1.21 |
| `manifest.json` | SHA-256 кожного файла, версії бібліотек і хеш параметрів |

## Як запускати

```sh
python -m pip install --require-hashes --only-binary=:all: -r mechanical/requirements-mech.txt   # x86_64 Linux, CPython 3.12
python mechanical/build.py --fetch-vendor /tmp/vendor-step            # STEP Radxa, SHA-256 перевіряється
python mechanical/build.py --vendor-cache /tmp/vendor-step --offline  # перегенерувати generated/
python mechanical/build.py --check --vendor-cache /tmp/vendor-step --offline  # побайтова звірка
python mechanical/build.py --gate                                     # FAIL-рядки звіту зупиняють CI
python -m unittest discover -s mechanical/tests
```

CI — `.github/workflows/sr-rx-mech.yml` (x86_64): встановлює закріплений стек, завантажує STEP постачальника, запускає тести, перегенеровує все в тимчасову теку й порівнює з `generated/` байт у байт; якщо щось відрізняється, артефакт `mech-regenerated` містить патч, який застосовується окремим комітом `GENERATED: …`. Еталон байтів — цей запуск (x86_64 Linux, закріплений стек). Числа в STEP округлено до 1e-9 мм, а STL пише власний writer із вершинами, округленими до 1e-4 мм, тож шум бібліотеки C зникає; на іншій платформі тріангуляція пласких граней і апроксимація сплайнів усе ж можуть відрізнятися в останніх знаках. Тому на Windows/macOS звіряйте з `--check --portable`: креслення, DXF, PDF і контракт плат — побайтово, STEP/STL — за об'ємом, габаритом і кількістю трикутників (`fit-report.json` → `volumes_cm3`); без `--vendor-cache` файли, що залежать від STEP Radxa (`vendor-fit.json`, M-10, `enclosure.pdf`), не порівнюються.

## Перевірки (усі — модель)

- **Конверти**: усі елементи `layout.items` попарно й зі структурою (пластина, кутники, бобишки, стінки РЧ-відсіку); зазор <0.5 мм — у списку «тісні місця». До конвертів входять охолоджувач A (Cu-блок, зона ребер, вентилятор), внутрішні частини панельних роз'ємів за кресленнями виробників (`nut.*`: корпус SMA-прохідника 8 HEX — гайка зовні; шайба, гайка й решта різьби F VFA340; кути гайки й чашки GX12), траса кабелю HDMI (`hdmi_*`, резерви), зовнішній резерв гермовводу T7.
- **Тіла B-rep** (`interference.py`): кожен конверт перетинається з реальною геометрією оболонок (радіуси кутів, пояс шва, бобишки, ребра, майданчики), пластини, кутників, РЧ-відсіку, п'єдесталу, бобишки UFS і лотка; перетини за задумом (плата на своїх стійках, Lime на п'єдесталі) названо явно. Усі пари тіл (оболонки, кришка лючка, козирок, лоток, тримач T7, пластина, кутники, п'єдестал, бобишка UFS, стінки й кришка РЧ-відсіку) перевіряються тіло проти тіла без винятків для скріплених деталей: дотик — це нульовий об'єм. Кожна деталь має бути одним тілом (без «висячих» бобишок).
- **Правила** (`rules.py`): відстані UFS — п'єдестал/регулятори ≥30, IP2368 — елементи ≥10, пакет енкодера ≤6.5, кнопки, гніздо гайки 1/4-20, отвори пластини й PEM від країв, гвинти шва всередині паза, вирізи бічних граней на пласкій частині й поза поясом шва, клапани (посадка, довжина різьби, отвір у піні батареї), панель кнопки живлення, модулі на платі в межах висоти плати, охолоджувач A (зона 32 x 31, вентилятор ≥10 над платою), різьба кожного панельного порту для стикування (R-SMA-THREAD), внутрішні конверти прохідників (R-BULKHEAD-NUTS), крок ряду нижньої грані (R-BOTTOM-PITCH), прохідники й гермоввід стінок S-band pod (R-POD-WALL), траса HDMI (OPEN).
- **Доступ і виступи** (`interference.py`, B-rep): до кожного гвинта шва, лючка й тримача T7 — прямий шлях інструмента ззовні (R-TOOL-ACCESS; знімна деталь може закривати гвинт шва, лише якщо її власні гвинти доступні); у диску площадки штатива ⌀50 нічого не виступає вище цоколя (R-TRIPOD-DISC); мішок 23 x 30 см рахується з глибиною закритого пристрою з усіма виступами.
- **Термоінтерфейси** (`thermal.py`): товщина Gelid GP-Ultimate під стиск 10-30 % і розкрій листів 90 x 50.
- **Ущільнення**: стиск і заповнення паза за правилом статичного ущільнення, довжина шнура, прольоти між гвинтами.
- **Антени**: розмір кожної частини за правилом build/06 §0 і відстані стиків Yagi до елементів.
- **STEP постачальника**: розміри плати й висоти роз'ємів Q6A з параметрів проти STEP V1.21.

## Друк (параметри `params/mechanical.json` → `print`)

Polymaker ASA White PF01002, шар 0.2 мм, 4 периметри, заповнення 30 %; бобишка гайки 1/4-20 — 100 % (STACK §2.9, §5.8); закрита вентильована камера. Бобишки при стінках друкуються без підтримки (навис від стінки не більше половини діаметра бобишки). Вставки CNC Kitchen M3x5.7 — у бобишки шва й лючка.

## Що лишається TBD / OPEN

- Деталі без даташита в пакеті: розміри V4L, Flamingo+ (резерв як у SAWbird+), висоти HDMI-плати й IP2368, глибина гнізда GX16, розетки USB-подовжувачів, гайки PV6 і клапанів LTW, проставка гребінки модулів Pololu, товщина пакета дисплея — у `parts.json` зі статусом `assumption`.
